# مقایسه قبل/بعد معماری CSS (فارسی)

این سند مزایا و تفاوت‌های معماری جدید CSS را نسبت به ساختار قدیمی نشان می‌دهد. داده‌ها بر اساس ساختار پروژه پس از refactor (PR #181/#182/#184) جمع‌بندی شده‌اند.

## خلاصه اجرایی
- **ساختار ماژولار ۴ لایه** جایگزین فایل‌های پراکنده شده است.
- **Theme-aware** با `data-theme` به‌جای چندین فایل جداگانه.
- **کاهش تداخل استایل‌ها** به کمک متغیرهای متمرکز و naming یکسان.
- **بهبود خوانایی و نگهداشت** با پوشه‌های عددگذاری‌شده و Entry واحد (`app.css`).

## مقایسه ساختار

| مورد | قبل | بعد |
| ---- | ---- | --- |
| ورودی اصلی | چند فایل (`app-mobile.css`, `admin-ui.css`, فایل‌های page-level`) | یک ورودی (`app.css`) که همه لایه‌ها را import می‌کند |
| سازمان‌دهی | ترکیب فایل‌های سراسری و in-page بدون مرز مشخص | چهار لایه: Foundation, Components, Layouts, Views |
| Theme | فایل‌های جدا برای admin/user | سوئیچ با `data-theme` و متغیرهای مشترک |
| Naming | کلاس‌های ناهمسان (btn-primary، card-box، ...) | BEM ساده + utilities یکنواخت |
| RTL | پراکنده و پر از override | RTL-first در Foundation |

## مقایسه حجم (نمونه عددی)

| شاخص | قبل | بعد |
| ---- | ---- | --- |
| تعداد فایل‌های اصلی | ~8 فایل پراکنده | 1 ورودی + 4 لایه | 
| خطوط CSS تکراری | زیاد (duplicate vars) | کاهش با تجمیع در `variables.css` |
| هزینه نگهداشت | بالا (وابستگی مخلوط) | متوسط/پایین (تفکیک مسئولیت) |

> اعداد بالا تقریبی هستند و بسته به حذف فایل‌های legacy ممکن است تغییر کنند؛ تمرکز بر کاهش تکرار و یکتاسازی ورودی است.

## مقایسه عملکرد

- **لود اولیه:** یک درخواست CSS اصلی به‌جای چندین درخواست جداگانه.
- **کش بهتر:** تغییرات theme عمدتاً روی CSS variables انجام می‌شود؛ کش فایل ثابت می‌ماند.
- **سازگاری RTL:** عدم نیاز به override پرهزینه در runtime.
- **قابلیت tree-shake دستی:** امکان حذف فایل‌های لایه‌ای که در یک صفحه استفاده نمی‌شوند (در صورت نیاز).

| سناریو | قبل | بعد |
| ------ | ---- | --- |
| تغییر رنگ برند | ویرایش چند فایل پراکنده | ویرایش متغیرها در `1-foundation/variables.css` |
| اضافه‌کردن کامپوننت | افزودن استایل در صفحه و فایل عمومی | افزودن فایل در `2-components/` و import در `app.css` |
| تم جدید | نیاز به فایل CSS جدا | تعریف theme جدید با `[data-theme]` و متغیرها |

## مزایای ساختار جدید
- سازگاری theme و RTL از روز اول.
- کاهش تداخل specificity و نیاز به `!important`.
- ناوبری سریع‌تر بین فایل‌ها به کمک عددگذاری لایه‌ها.
- امکان مستندسازی و دموهای مجزا برای هر لایه/کامپوننت.
- آماده برای افزوده شدن layout utilities (grid/spacing) بدون لمس فایل‌های دیگر.

## توصیه‌های استفاده
- همیشه از `app.css` به‌عنوان ورودی واحد استفاده کنید.
- فایل‌های legacy را پس از مهاجرت حذف یا غیرفعال کنید تا تداخلی ایجاد نشود.
- برای صفحات خاص، overrideها را در `4-views/` نگه دارید تا global styles تمیز بماند.
- قبل از Merge، از جدول mapping در `CSS_MIGRATION_GUIDE_FA.md` برای تطبیق کلاس‌ها استفاده کنید.
